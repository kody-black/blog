# 网页写作指南

## 首次连接

1. 打开 https://app.pagescms.org/ ，用 GitHub 登录。
2. 按提示安装 Pages CMS GitHub App，只授权 `kody-black/blog`。
3. 选择 `kody-black/blog` 仓库和 `main` 分支，后台会读取根目录 `.pages.yml`。
4. 打开「博客文章」，新建一篇测试草稿。先不要修改旧文章。

## 新建与发布

- 填写标题、日期和摘要，按需要添加分类与标签。
- 文件名在创建时可编辑，建议用简短英文，例如 `2026-09-08-first-post.md`；发布后不要改路径，以免影响链接和评论。
- 用正文工具栏排版、添加代码块及上传图片；封面在独立的「封面」字段上传。
- 默认开启「草稿」。保存会提交到 GitHub，但不显示在网站上。
- 准备好后关闭「草稿」并保存。查看仓库 Actions，等待构建与部署成功，再刷新博客。
- 日期不要选未来时间；目前没有定时发布任务，到时间也不会自动重新构建。
- 草稿不是隐私保护：公开仓库中的草稿、图片和 Git 历史都能被他人看到。

## 图片与旧文章

正文图片存入 `static/uploads`，生成 `/blog/uploads/...` 链接。
封面存入 `assets/uploads/covers`，由 Blowfish/Hugo 读取处理。
不要把正文图片路径手动填入封面字段；使用对应上传入口。
建议上传压缩过的图片，避免大图持续增加 Git 仓库体积。

旧文章目录和链接保持不变，新文章使用独立 Markdown 文件。
含 `{{< ... >}}` 的 Hugo 短代码、复杂 HTML 或特殊表格不保证可视化往返编辑无损。
这些旧文章优先继续使用 GitHub 源码编辑；后台源码切换也应先用副本测试。
编辑器预览不是完整 Hugo 页面预览。
此配置禁用文章删除和重命名入口，减少误操作；不是 GitHub 权限隔离。

## 首次验收

授权后先创建测试草稿，确认标题、分类、代码块、正文图片和封面可保存。
确认保存后草稿未出现在首页。检查 GitHub 差异，确认 YAML 与正文正常。
只有确认内容可以公开后再关闭草稿，验证文章页与图片；不要发布敏感测试内容。
未完成这一步前，不能视为已验证 CMS 编辑器端到端兼容性。

网页后台保存后，在本地继续工作前先 `git pull --ff-only`，避免本地与远端冲突。
若误改文章，可从 GitHub 提交历史恢复；不要随意强制推送。
